# Internet Speed Checker (test task)

Консольный скрипт в двух вариантах — Node.js (`src/speed-check.js`) и Python (`speed_check.py`). Оба делают одно и то же:

- принимает URL ресурса для скачивания;
- выполняет 10 последовательных GET-запросов по одному соединению (keep-alive);
- дожидается полного получения тела каждого ответа;
- вычисляет среднее время запроса и общий объём скачанных данных;
- выводит скорость скачивания в консоль.

## Требования

- Node.js 18+ **или** Python 3.10+
- Внешних зависимостей нет (только стандартная библиотека)

## Запуск

Node.js:

```bash
npm start -- "https://proof.ovh.net/files/1Mb.dat"
```

Python:

```bash
python3 speed_check.py "https://proof.ovh.net/files/1Mb.dat"
```

## Что считается

- Количество запросов: **10** (фиксировано)
- Среднее время запроса: **ms**
- Общий объём: **B** (и человекочитаемый формат)
- Скорость скачивания:
  - **MiB/s** (мебибайт в секунду, 1 MiB = 1024 × 1024 B)
  - **Mbit/s** (мегабит в секунду, десятичные мегабиты)

## Выполнение запроса

Каждый из 10 запросов выполняется последовательно и включает следующие этапы:

1. Разбор URL на схему, хост и путь.
2. Разрешение имени хоста в IP-адрес (DNS).
3. Установка TCP-соединения; для HTTPS дополнительно выполняется TLS-handshake.
4. Отправка запроса `GET <путь>`.
5. Получение статуса, заголовков и тела ответа.

Этапы 2–4 выполняются стандартной библиотекой (`http.client` в Python, модули `http`/`https` в Node.js). Соединение открывается один раз и переиспользуется для всех запросов серии (keep-alive), поэтому первый запрос дольше остальных: в его время входят DNS, TCP и TLS. Остальные запросы отражают скорость передачи данных.

Редиректы (3xx) отрабатываются автоматически, не более 5 переходов. Если сервер закрыл простаивающее соединение, Python-версия один раз переподключается.

## Методика измерения

Объём и время определяются по фактическому обмену данными, а не по заголовкам ответа.

**Объём.** Тело ответа читается блоками, размер каждого блока суммируется. Заголовок `Content-Length` не используется: он может отсутствовать (`Transfer-Encoding: chunked`), содержать некорректное значение или не совпадать с объёмом переданных данных при сжатии.

**Время.** Отсчёт начинается перед отправкой запроса и завершается после получения последнего байта тела. Получение заголовков не считается завершением запроса. Для измерения используется монотонный таймер (`time.perf_counter()` в Python, `performance.now()` в Node.js), не зависящий от корректировки системных часов.

**Формулы:**

- среднее время запроса = сумма длительностей всех запросов / 10;
- скорость скачивания = общий объём / суммарная длительность всех запросов.

## Пример вывода

```text
#1: 145.20 ms, 1.00 MiB
...
#10: 132.88 ms, 1.00 MiB

Summary
Requests: 10
Average time: 139.84 ms
Total downloaded: 10.00 MiB (10485760 B)
Download speed: 7.151 MiB/s
Download speed: 59.955 Mbit/s
```

## Обработка ошибок

При некорректном URL, ответе со статусом вне диапазона 2xx, сетевой ошибке или таймауте (30 с) скрипт выводит сообщение `Error: ...` в stderr и завершается с кодом 1. При запуске без аргумента выводится подсказка по использованию.

## Тесты

Интеграционный тест поднимает локальный HTTP/1.1-сервер с файлом известного размера и проверяет обе реализации: ровно 10 запросов, точный объём, одно TCP-соединение на всю серию, обработку редиректа, ответ 404 и запуск без аргумента. Доступ в интернет не требуется.

```bash
python3 -m unittest -v tests.test_scripts
```
